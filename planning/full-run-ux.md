- **confirmed:** 전체48모듈·개별해금·T05/T06이 아직 구현되지 않았다면 실제 구현 수와 미구현 범위를 개발 정보로 정직하게 표시한다. 이를 완성 콘텐츠처럼 예고하지 않는다.

## 2. 상태별 흐름과 정보 위계

| 상태 | 항상 먼저 보일 것 | 행동·피드백 |
| --- | --- | --- |
| SHOP | 현재 HP/골드/방문, 다음 최대3개 웨이브의 ID·실제 적 수·종류/특수 표식 | 거래와 `상점 접기`. 접은 같은 방문의 재개 권한은 session의 실제 권한을 표시하며, wave 시작 뒤에는 비활성 이유를 보인다 |
| PREPARE | 다음 웨이브 한 개의 실제 ID·적 수·입구/종류/특수 규칙, HP/골드, 배치 상태 | `Wnn 시작`. `nextWaveIndex <= 15`이고 session이 시작을 허용할 때만 활성. 상점 재개는 해당 visit 권한이 있을 때만 활성 |
| COMBAT/PAUSE | 현재 wave, **battle HP 우선**, 생존 적/미출현 수, 속도·정지 이유 | 기존 1×/2×/pause/focus 규칙 유지. run 시작 HP를 live HP처럼 표시하지 않음 |
| RESULT | 승리/패배, 보스 처치·탈출 또는 HP0 등 종료 이유, 저장 확인 상태 | `새 판`→확인/취소. 확인 전 meta/run/save 불변. 취소하면 같은 RESULT로 돌아감 |
| SAVE_ERROR | 저장되지 않은 상태와 재시도/안전 종료 | 새 판·웨이브 시작·거래를 성공처럼 제공하지 않음 |

SHOP 예고는 현재 `nextWaveIndex`부터 존재하는 항목만 최대3개 표시한다. PREPARE는 그중 바로 다음 한 개를 더 자세히 보여준다. 적 수, 종류, 입구, 특수 표식은 콘텐츠 정의의 실제 그룹을 집계하며 W01–W03 숫자나 15개 배열을 UI에 복제하지 않는다. 남은 웨이브가 3개보다 적으면 빈 가짜 행을 만들지 않는다.

각 SHOP 예고 행과 PREPARE의 다음 웨이브에는 `편성 상세` 진입이 있다. 상세는 `defs.waves[].groups`의 **정의 순서**대로 `groupId`, 입구, 적 종류, 수량, `firstTick`, `intervalTicks`, 특수 표식을 모두 보여준다. `groupId`는 시간 정렬 번호가 아니며 그룹별 출현 시간은 서로 겹칠 수 있음을 함께 알린다. 합계 행만으로 이 정보를 대신하지 않는다. 480×270에서는 같은 문맥 패널을 상세로 교체하고 `돌아가기`로 구매·시작 화면에 복귀한다. 주 안내·HP·골드는 유지되며, 상세 열기/닫기는 View 로컬 표시 상태라 RNG·pause·run·save generation을 바꾸지 않는다. 보스 규칙 토글은 이 편성 상세와 별도이며 우선 열람 후 닫으면 직전 편성 상세로 돌아온다.

구간 상점은 W3/6/9/12 완료 뒤 S01/S02/S03/S04다. 각 visit은 바로 다음 combat 시작 전까지만 다시 열 수 있다. 알려진 구버전 S01/W04 저장을 migration한 뒤에는 W04가 정상 다음 행동이며, 이전 `developmentComplete` 또는 “현재 버전은 여기까지” 표시로 막지 않는다. 첫 무료 타워 안내는 **S00 + nextWaveIndex=1**인 첫 시작 문맥에만 보이고 S01 이후에는 재사용하지 않는다.

`보스 규칙`은 SHOP/PREPARE/COMBAT/PAUSE/RESULT에서 접근 가능한 상세 토글이다. 열면 W15의 단일 E05, HP 600 미만에서 다음 이동 tick부터 기본 속도×1.20, 처치 즉시 승리, 출구 도달 즉시 패배, 같은 tick 패배 우선 규칙을 현재 콘텐츠/규칙 메타데이터로 보여준다. 열람은 RNG·시간·돈·선택을 바꾸거나 전투를 자동 정지하지 않는다. 닫으면 직전 문맥 패널로 복귀한다.

## 3. 인벤토리와 입력

- 6개/페이지의 두 열 목록을 유지한다. `이전`, `다음`, `n/m`, 전체 보유 수를 함께 보여주고 첫/마지막 페이지 버튼은 비활성 이유가 드러나야 한다.
- 페이지 수는 `ceil(실제 instance 수 / 6)`으로 계산한다. 구매·복원·페이지 전환 뒤 유효 범위로 보정하며 빈 페이지에 머물지 않는다.
- 선택은 행 번호가 아니라 `instanceId`에 고정한다. 페이지를 바꿔도 선택은 유지하고, 선택 개체가 다른 페이지에 있으면 이름·번호·배치/패치 상태를 문맥 상세에 계속 표시한다.
- 새 타워 구매 직후에는 그 개체가 있는 페이지로 이동해 선택 결과를 보인다. 취소된 구매는 페이지·선택·골드·저장을 바꾸지 않는다.
- 명시적 페이지 버튼이 기본 경로다. 포인터가 목록 위에 있을 때의 wheel 페이지 이동은 보조 경로이며 뒤 전장 클릭/배치로 전달하지 않는다. letterbox·pause·focus 규칙은 DR-UX-001 r2를 유지한다.

## 4. 기능 화면 배치 의도와 개발 표시

전장/인벤토리와 오른쪽 문맥 패널의 큰 구조는 유지한다. SHOP의 다음3웨이브, PREPARE의 다음1웨이브, 보스 규칙, RESULT 확인은 동시에 축소 표시하지 않고 같은 문맥 패널을 상태/토글에 따라 교체한다. 주 행동과 금지 이유가 개발 범위 문구보다 먼저 보인다.

한글은 기존 native viewport rasterization을 유지한다. 월드 캔버스는 480×270 nearest 정수 배율/letterbox를 사용하되, 텍스트는 최종 viewport 배율에서 래스터화한다. 480×270에서 버튼·지역 안내와 겹치지 않고 960×540/1440×810에서 획이 무너지지 않아야 한다. 정확한 픽셀·최종 카피·정식 시각 처리는 후속 formal UI 소유다.

개발 표시는 고정 문장 속 숫자가 아니라 기능 capability 데이터의 `implemented/planned`를 사용한다. 최소한 `모듈 {구현}/{전체48}`, `T05/T06 미구현`, `개별 해금 미구현`을 주 행동 아래의 보조 정보로 구분한다. 실제로 구현된 수가 바뀌면 UI 문자열을 별도 수정하지 않아도 값이 따라가야 한다.

## 5. 관측 시나리오와 인계

1. **이어하기:** known-old W03 저장을 메모리/격리 fixture로 읽어 W04 PREPARE에 진입한다. 실제 W04 정보, 활성 시작, live가 아닌 run HP가 준비 상태에 보이며 사용자 저장은 쓰지 않는다.
2. **상점 방문:** 3웨이브 구간 완료 뒤 새 방문에서 다음 최대3개 예고를 본다. 접은 뒤 같은 visit 권한이 있으면 재개되고, 다음 wave 시작 뒤 이전 방문은 비활성 이유와 함께 닫힌다.
3. **7기 이상:** 7번째 타워를 구매해 두 번째 페이지로 이동·선택한다. 1페이지로 돌아가도 선택 대상은 바뀌지 않고, 다시 접근해 배치할 수 있다.
4. **W15/보스:** PREPARE에서 실제 보스 포함 정보를 보고 규칙 상세를 열었다 닫은 뒤 시작한다. 전투 중 HP는 battle 값을 표시한다. 보스 처치/탈출/동tick 패배가 각각 한 번만 RESULT로 이어진다.
5. **새 판:** RESULT에서 새 판을 눌러 확인 화면을 연다. 취소는 상태·generation 불변, 확인은 기술 계약에 따라 meta를 보존하고 새 run만 초기화한다. 진행 중에는 같은 행동이 존재하지 않는다.

후속 playable-functional 구현은 이 흐름, 실제 데이터 집계, page/instance 선택, live HP, 금지 이유를 보존한다. new-run UI 명령 이름은 `requestNewRun()`, `cancelNewRun()`, `confirmNewRun()`이고 표시 상태는 `getState().newRunDraft`로 고정한다. 구현자는 DR-RUN-002의 콘텐츠·상점 visit·RESULT/new-run 상태 계약을 UI에서 재정의하지 않는다. 별도 검증자는 C401–C406, 480/960 텍스트 fit, 정상/금지 버튼, 저장 불변을 확인한다. 이 walkthrough는 실제 플레이·사람 사용성·정식 visual acceptance 결과가 아니다.
