# Independent style and motion samples

Use this guide after checking the [sample library](sample-library.md). Present matching prebuilt samples first; if sufficient, do not regenerate them. Use the production guidance only for an evidenced gap and write that addition project-locally. Start from the project's functional family inventory, unresolved choices, supported languages and existing decisions. Buttons, frames, blocks or labels are possible families, not a required checklist. These menus help expose meaningful choices; they do not prescribe a game, engine, viewport, font, language, candidate count or exact combination set.

## 1. Choose axes that change the decision

For each relevant family, identify which choices remain open and which are already selected or functionally protected. Use the following starting menu only where applicable:

| Axis | Possible starting alternatives | What the decision-maker should be able to judge |
| --- | --- | --- |
| Surface and depth | flat fill; shallow raised or recessed surface | Optical weight, edge separation and pressed/selected readability, not a palette swap |
| Contour | square; chamfered; softly rounded | Silhouette, corner rhythm, joins and clearance with actual content |
| Emphasis | outline-led; filled emphasis; restrained accent | Relative prominence and state distinction without changing meaning |
| Information density | explicit labels with supporting text; compact wording/grouping; reduced visible support | Whether the same action, unit, state and error cause remain understandable and accessible |
| Typography | several actual feasible fonts with visibly different proportions or character | Reading rhythm, hierarchy, numeric alignment, glyph support and wrapping, not a font-name list |
| Motion language | snap/settle; compression and restoration; elastic recoil; fade with displacement | Onset, emphasis or impact, hold, overshoot and recovery appropriate to the event |

Offer materially distinct feasible options for each consequential unresolved choice as required by the direction contract. Do not make every family use every menu item. Preserve already valid selections. Explain excluded or unsupported alternatives rather than presenting an unavailable font or inaccessible treatment as a viable option.

## 2. Make differences independently editable

Use a small, source-backed specimen for each family with comparable content, state, size and viewing conditions. Keep geometry, surface treatment, typography, density and motion parameters separate in the sample source or tool layers. For an axis comparison, hold unrelated axes fixed and label intentional differences. Do not replace comparison with a single heavily art-directed screen.

Assign a stable family ID plus form/style and motion-event candidate IDs, revisions, sample paths/selectors and source fingerprints. A shared page with independent replay/selection is valid; respect an explicit one-page request. Export an independently inspectable static artifact for each form candidate and replayable evidence for each applicable family/style/event. A contact sheet or viewer may index these artifacts but is optional; selecting or revising one candidate must not require selecting a whole board. Shared source, font fixtures or playback controls are allowed when they preserve individual identities and outputs.

Use representative combinations to investigate real interactions, such as a dense label in a narrow contour. Do not generate the full Cartesian product of every font, corner, depth and timing option. If an interaction is unresolved, add the affected comparison and explain why it is needed.

## 3. Show event-specific motion

Select events from the family's actual state and interaction contract. Where relevant, show entering, selection or activation, emphasis/error feedback, release and exit. These are examples, not permission to add new product states or interaction behavior.

For each motion candidate, retain a replayable isolated event with a visible initial state, transition or impact, and settled/returned state. Provide a way to replay that event without waiting for an unrelated long sequence. Use the same event, content and observation conditions when comparing movement languages. Record the timing and amplitude so a requested change can target one property, but do not treat different speed numbers on the same curve as sufficient stylistic diversity.

A snap with a clean settle, a compression-and-restoration gesture, an elastic recoil, and a fade/slide communicate differently; choose feasible languages appropriate to the event. The guide does not require all of them or any particular duration. One global animation reel cannot stand in for unrepresented family/style/event combinations. A justified no-motion treatment may be a real option; label its scope and reason.

## 4. Compare text and fonts without losing information

Render actual candidate font files or verified platform fonts. Record source, availability, usage/licensing constraints, glyph coverage and any explicit fallback. Availability on the author's machine is not permission to bundle the font. Do not silently simulate another font with the same fallback.

Use actual representative wording, numerals, units, short/long labels and error text for the project's supported languages. Inspect line breaks, expansion, contraction, missing glyphs, clipping and state clarity at the intended specimen size. If additional languages are unresolved, record that limit and retain language-specific input/coverage slots for later evaluation; do not invent translations or new localization requirements.

Density is a choice, not an automatic preference for minimal text. Compare equivalent functional meaning, keeping required labels, units, status and error causes visible or available through already supported keyboard and accessibility paths. Ambiguous icon-only replacements, omitted error causes and invented hidden interactions are not feasible reductions. If a protected content change is necessary, return it to its content owner rather than hiding it inside the styling choice.

## 5. Check sufficiency before requesting selection

Inspect all retained form samples at their intended size and actually play their motion evidence. Check:

- Every required family and consequential unresolved axis has usable, materially different alternatives; cosmetic recolors, tiny corner changes and speed-only motion variants cannot cover a major unresolved choice.
- Each applicable family/style/event has replayable evidence or an explicit justified no-motion scope. The difference in onset, emphasis and recovery is observable.
- Actual content, font and language coverage support the density/typography comparison; unsupported glyphs and lost meaning are failures, not tradeoffs to conceal.
- Craft is sufficient for an informed choice: edges, spacing, type hierarchy, optical balance, state distinction and motion recovery are deliberate and readable. Source/hash parity alone does not establish this.
- A requested family or axis can be revised independently, with unaffected selections preserved. IDs, source, provenance and comparison conditions are clear.

If options do not expose the meaningful decision, repair or add focused alternatives before asking the user to choose. The independent verifier evaluates this same scope; author preference does not substitute for its evidence.

Record selection, rejection and unresolved choices by family and axis. Separately assess compatibility of selected colors, optical weights, type hierarchy and motion behavior across families; incompatible mixes need an explicit adjustment proposal, not silent replacement or automatic global reselection. This can use focused comparisons and does not require a full-screen mockup. Only authorized selections proceed to investigation of compatible existing templates and addition of missing coverage. Sample files do not become approved templates by being reusable code.

## Optional reference links

When presenting style, component or motion choices, explicitly offer an optional URL field alongside candidate selection. For example: "Choose a candidate, request a focused revision, or optionally add a reference URL. For a link, you may indicate its scope and what to study or avoid; you can continue without one." This is a selection prompt/option-map input, not a requirement to implement a new product form. Scope can be the shared visual language, one family, a form or other variation axis, or a particular motion event. Record supplied scope and desired/avoided elements; if omitted, propose a narrow interpretation for review rather than treating the whole reference as desired.

Open each supplied URL with an available permitted tool and inspect the relevant content; for motion, observe playable evidence rather than inferring movement from a still. Record source URL/title, access status, what was actually observed and where (such as section or timestamp), separately from licensing, attribution and asset/wording replication boundaries. Access is not a reuse license. If inaccessible, record the limitation and do not invent observations or bypass access restrictions; keep unaffected work moving and offer optional replacement evidence only when that reference is needed for the affected choice.

A link supplies reference evidence, not automatic approval of its appearance, text, features or interactions. Translate observed desired elements into bounded candidate changes under existing functional constraints. Record used, partially used or not used, with reasons (including access limits, conflicts, unavailable rights or lack of relevance); no supplied link must silently disappear. When no link is supplied, record that neutral status and proceed.

For a new or changed link, identify the affected family, axis or motion-event candidate IDs and reopen only those decisions and their affected compatibility checks. Preserve unrelated selections and valid evidence. Present the resulting revisions for the applicable authorized selection; do not silently replace an earlier approved template or promote referenced designs into one.
