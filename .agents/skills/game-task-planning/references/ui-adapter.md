# 통합 UI 연결 · v2

같은 묶음의 UI 스킬과 schema를 사용한다. 별도 UI 설치는 필요 없다. 직접 호출에도 적용한다. 화면·상태·target, 원본 규칙 locator/hash, 역할 카드, 언어와 고정 검증 범위를 기존 인계 기록으로 전달한다. UI 표를 복제하지 않고 공통 envelope만 연결한다.

## 최소 개입 결정 규칙

아래 순서로 처리하며 단계 종료를 사용자 응답 대기로 바꾸지 않는다.

1. 현재 요구에 유효한 기존 결정과 승인을 재사용한다. 승인된 동작·시각 결과로 복구하거나 유지하는 작업은 원본 승인과 현재 후보의 대응 근거를 기록하고 진행한다. 예전 빌드의 검증 결과를 새 빌드의 통과로 복사하지 않는다.
2. 요청 범위 안의 구현 방법·정렬·도구 선택은 담당자가 결정한다. 취향·제품 선택도 명시된 위임 범위 안이면 감독 또는 지정된 결정자가 선택한다. 작성자의 취향만으로 승인하지 않는다.
3. 새로운 제품 선택이라도 명시적 위임이 있으면 그 범위에서 결정한다. 요구 충돌, 결정에 필수인 입력 부재, 위임 밖의 중대한 제품 선택, 명시적으로 사람에게 남긴 승인만 사용자에게 묻는다. 먼저 근거·추천안·영향·검토 가능한 후보를 준비하고, 감독이 남은 질문을 묶는다. 무응답은 승인이나 위임이 아니다. 영향 없는 작업은 계속한다.

UI 문서의 approved/selected 및 fidelity decision은 이 규칙으로 충족한다. 실제 사람 승인, 위임 결정, 기존 승인 재사용을 서로 다른 근거로 기록하며 자동 결정을 사람 승인으로 표시하지 않는다. 프로젝트/사용자가 명시한 human-only 조건은 유효한 권한 변경 없이 해제하지 않는다. 전문 역할의 산출물 종료는 감독에게 반환하는 경계이며, 충족된 다음 단계를 시작할 때 재승인을 요구하지 않는다.

## 초기 화면과 수정 반복

[빠른 수정 경로](ui-fast-iteration.md)는 미정 스타일·템플릿이 있어도 알려진 실제 내용/target/상태의 수정 가능한 화면 초안을 허용한다. 아래 선행 순서는 정식 승인 산출물에 적용하며, 이 초안을 차단하지 않는다. 초안은 승인된 시안·catalog·제품 구현이 아니다. 부분 runtime 검증에서는 현재 재관측과 검증된 역사적 증거 재사용을 구분하고 전체 필수 coverage와 원래 raw identity를 유지한다. 게임 기능을 먼저 플레이 가능하게 만드는 임시 제품 UI는 이 탐색 초안과 구분한다. 승인된 기능·입력 계약을 바탕으로 game-ui-implementation의 playable functional interface 모드에서 실제 target runtime에 구현·기능 검증하며, 최종 시각 승인과 fidelity 수용은 후속 정식 UI 경로로 남긴다.

## UX 설계 선행

새 정식 화면이나 과업 흐름·정보 위계·내비게이션·피드백·내용 밀집 배치가 실질적으로 바뀌는 UI에는 `game-ui-ux-design`이 제품 근거와 실제 내용/대상으로 플레이어 과업·흐름·정보/행동 우선순위·배치 의도를 먼저 결정한다. 모든 정식 화면은 현재 범위를 덮는 UX 결정 ID/revision 또는 기존 승인 UX 결정의 호환 재사용 근거를 연결한다. 순수 외형/기술 수리에서 과업·흐름·위계가 그대로이면 UX 재작성을 요구하지 않는다. 빠른 탐색 초안에는 잠정 UX framing을 사용하되 정식 UX 결정으로 표시하지 않는다. UX 결정은 제품 행동 승인, 아트 스타일 선택, 컴포넌트 승인, 화면 명세나 사용자 테스트를 대신하지 않는다. 새 컴포넌트 구조와 정식 화면 명세·목업은 이 UX 결정을 소비하고, 상충하면 해당 소유자에게 반환한다.

## 스타일과 템플릿 선행 순서

기존에 선택된 스타일·모션이 현재 요청과 호환되면 정확한 근거로 재사용한다. 없거나 새 스타일 선택이 필요하면 먼저 game-ui-art-direction의 sample-library manifest를 조회하여 적합한 기존 표본을 그대로 제시한다. 충분하면 재생성하지 않고 exact ID/version/source를 연결한다. 부족한 유형만 프로젝트 경로에서 만들고 독립 품질·권리·이식성 검토 후 원본 담당자가 공용 라이브러리에 한 번 추가한다. library-ready는 사용자 선택/template 승인과 별개이며 실제 언어·내용 적합성 검증을 대체하지 않는다. 한 페이지에서도 후보별 ID/독립 replay로 선택 가능하며 별도 HTML을 강제하지 않는다. 필요한 신규 옵션에는 game-ui-art-direction이 미정인 중요한 스타일·모션 선택마다 실질적으로 다른 둘 이상의 비교 옵션을 동일한 내용·상태·크기로 보여주고, 모션은 재생 가능한 샘플로 제시한다. 기능상 필요한 컴포넌트 가족별로 형태·스타일·모션의 독립 ID와 revision을 두고, 각 적용 스타일의 모션 재생 또는 근거 있는 무모션 사유를 연결한다. 통합 비교판은 선택 사항이며 개별 가족의 비교·선택·수정에 선행 조건이 될 수 없다. 선택에 중요한 가족·스타일별 모션·사건이 빠졌다면 해당 샘플을 보완한 뒤 가족별 선택·거절·미해결 및 조합 호환성을 기록한다. 모양·깊이·모서리·텍스트 밀도·레이블/보조설명 표시·실제 폰트·모션 등 중요한 축은 프로젝트 입력에 따라 독립적으로 비교·선택하며 고정 목록이나 모든 조합 생성을 요구하지 않는다. 지원 언어의 실제 문구로 글꼴 커버리지/대체·길이 변화·줄바꿈·배치를 확인한다. 텍스트 최소화도 기능 의미·단위·상태·오류 원인 및 기존 키보드/접근성 경로의 필요한 정보 접근을 보존해야 하며 의미를 잃는 아이콘 대체를 허용하지 않는다. 언어·폰트·가족 목록은 프로젝트가 정한다. 한 가족이나 축의 변경으로 무관한 선택을 취소하거나 전체 묶음 재선택을 강제하지 않는다. 예약된 사용자 선택 또는 유효한 위임 결정의 권한은 그대로 유지한다. 그다음 game-ui-component-system이 필요한 컴포넌트의 기존 승인 템플릿을 재사용하고 빠진 가족만 실물 디자인 템플릿과 catalog에 추가·검증한다. game-ui-screen-spec과 game-ui-mockup은 선택된 스타일 및 해당 템플릿을 소비하며, 전체 UI는 가능한 한 템플릿으로 조합한다. 스타일 선택, 템플릿/catalog 결정, 전체 화면 선택, runtime 수용은 별도 결정이다. 새 스타일이나 템플릿으로 영향받는 downstream 근거만 다시 연다.

## 기존 인계 기록에 남길 값

| 값 | 소비 규칙 |
| --- | --- |
| decision ID, scope, candidate/revision, authority source | 원문 요청·기존 승인·위임 출처와 정확한 후보를 연결 |
| confirmed/delegated/proposed/unresolved, 선택/이유, 결정자 | delegated에는 실제 위임과 선택 필요. proposed/unresolved는 승인 아님 |
| 기존 승인 재사용 근거, 변경·보존 조건, 남은 human-only 조건 | 새 디자인·변경된 제약에 무조건 승계를 금지 |
| 현재 build/composite fingerprint, evidence IDs, 독립 판정 | 새 빌드는 현재 증거로 검증. 위임이나 과거 승인은 검증 대체 불가 |

명세·방향·목업은 해당 내용의 결정 근거를 각각 연결한다. 다른 문서의 승인만으로 자동 승인하지 않는다. 컴포넌트 catalog는 기존 schema와 fingerprint를 유지하고, 위임 승인자는 유효한 출처로 프로젝트 approvalAuthorities에 선언되어야 한다. 미등록 권한을 validator 통과용으로 만들어 넣지 않는다.

## 독립 검증과 반환

산출물 작성자와 별도 서브에이전트가 고정 기준 안에서 검증한다. 위임 결정자도 자기 산출물의 독립 검증자가 될 수 없다. 필수 art/UI 판정, 현재 증거, 승인된 편차 범위는 유지한다. P3 편차도 같은 결정 규칙으로 해당 편차·후보를 수용해야 하며 P0/P1/P2를 위임으로 면제하지 않는다.

검증 오류는 작성자가 반환된 범위만 수정하고 별도 검증자가 영향 기준만 재검증한다. 기존 재시도 한도를 지키며 범위 밖 발견은 새 작업이나 gate로 만들지 않는다. 검증 불가나 한도 소진은 막힌 범위와 근거를 반환하며 통과로 바꾸지 않는다.
